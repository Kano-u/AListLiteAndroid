# 同步上游更新

本文档说明：上游 `LeoHaoVIP/AListLiteAndroid` 更新后，如何把更新合并到本仓库并重新出包。

## 先分清两种"更新"

| 更新类型 | 表现 | 需要做什么 |
| --- | --- | --- |
| OpenList 后端更新 | 上游 OpenList 发新版（例如 4.2.6 → 4.3.0） | 什么都不用做，构建时会自动抓最新 OpenList 源码重新编译，版本号也同步写进 `Constants.java` |
| AListLite 本体更新 | 上游 Releases 出现新的 `v3.0.1-auto8` 之类 tag，或上游有了新提交 | 按下面的步骤合并 |

## 判断有没有本体更新

```powershell
cd C:\Users\Kano\Documents\ChatGPT\AListLiteAndroid
git fetch upstream
git log --oneline HEAD..upstream/master   # 有输出说明上游有新提交
```

也可以直接看上游 Releases 页面：https://github.com/LeoHaoVIP/AListLiteAndroid/releases

## 合并步骤

```powershell
git fetch upstream
git merge upstream/master
# 如果有冲突：编辑冲突文件，然后 git add 该文件，再 git commit
git push origin custom-userscript
```

推送后「0-编译检查」会自动验证；通过后触发发布（二选一）：

```powershell
# 方式一：GitHub 的 Actions 页面点 Run workflow，分支选 custom-userscript
# 方式二：推一个 build-* 标签
git tag -f build-20260915
git push -f origin build-20260915
```

## 可能会冲突的文件与处理原则

上游改动较大的文件正好也是我们改过的地方，冲突时原则是：上游的新功能照单接收，我们的这几处改动必须保留。

| 文件 | 我们改了什么 | 冲突时怎么处理 |
| --- | --- | --- |
| `app/build.gradle` | ABI 只保留 `arm64-v8a`、关闭 universal | 保留只编 arm64 |
| `AListLib/scripts/build_aar.sh` | gomobile 加 `-target=android/arm64`、复制全部 AAR | 保留 |
| `MainActivity.java` | 油猴脚本注入、静默更新检查 | 都保留（登录沿用上游的「一键登录」，未做改动） |
| `service/AlistService.java` | 启动成功只写日志、不再弹 Toast | 保留 |
| `UpdateChecker.java` | 增加 `interactive` 参数 | 保留，注意调用处要传参数 |
| `ExampleUnitTest.java` | 本机路径不存在时跳过 `configReadTest` | 保留 `Assume` 判断，否则 CI 单测必失败 |
| `window/`、`popup_menu_view.xml`、`strings.xml` | 新增「脚本管理」菜单与弹窗 | 我们的新增项和上游新增项都要保留 |
| `.gitignore` | 忽略签名密钥与构建中间产物 | 保留 |
| `.github/workflows/2-build-arm64-apk.yml` | 我们自己的发布流水线 | 上游没有同名文件，不会冲突 |

## 需要留意的风险

- 上游如果改了前端结构（例如登录页、路由），油猴脚本注入可能需要跟着微调（编译能过，但功能要重新验证）。
- 合并后建议在手机上过一遍：启动不再弹「已是最新版本」和「服务已开启」提示、脚本管理里的脚本仍能注入、一键登录、下载等功能正常。
